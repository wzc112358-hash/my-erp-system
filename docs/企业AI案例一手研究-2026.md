# 化工品 B2B 贸易企业 AI 落地案例一手研究

> 研究日期：2026-08-03
>
> 适用对象：已有 ERP（销售/采购合同、发票、收付款、招投标等），正在建设招投标采集 Agent 与新产品搜索分析 Agent 的中国化工品 B2B 贸易企业。

## 研究口径与证据局限

- 优先使用企业年报、企业官网、政府/监管网站和标准机构。云厂商客户案例仅作为有客户具名和具体做法的补充证据。
- “已公布效果”是企业或案例发布方公布的口径，不等同于经独立审计的财务收益。
- 本文严格区分“已实现”、“试点/测试结果”、“预期效果”和“未披露”，不将产品功能当作业务价值。
- 证据等级：`A` = 企业年报/政府或监管来源；`B` = 企业官网新闻；`C` = 技术供应商的具名客户案例。

## 结论先行

1. **化工贸易的第一个 AI 工程不是换大模型，而是产品、客户、供应商和合同的主数据工程。** Brenntag 先将非结构化的化工产品信息转成统一、多维的产品数据，再服务销售、客服与供需计划。
2. **优先选择“高频+有明确参照答案+可人工复核”的流程。** 销售订单录入、报价、运费发票核验、标书客观项比对已有最强的可迁移证据。
3. **Agent 不应绕开 ERP，而应作为 ERP 上的“读取-提议-审批-写回”层。** Synthomer 的做法是用物料目录、历史订单和客户数据提出匹配建议，员工确认后才创建订单。
4. **招投标与合同类场景的核心不是自动下结论，而是证据溯源、规则标准化和人机协同。** 深圳试点和华电案例都将 AI 放在辅助评审位置，保留专家/业务人员最终责任。
5. **规模化不是多造 Agent，而是统一知识、工具、权限、评测和审计。** 中国中化的“知识引擎-智能体引擎-AI 能力市集”三层解耦架构，比“每个部门单独搭一套”更适合后续扩展。
6. **收益必须回到业务账。** 每个用例在开发前要定义基线、对照组、人工复核率、错误成本和财务受益人；不以 token 量、Agent 数量或“用户觉得好用”代替 ROI。

## 一手/高可信案例

### 1. Brenntag：先治理化工品产品主数据，再做销售、客服和供需智能化

- **企业/场景**：全球化学品与配料分销商 Brenntag；产品信息治理、销售支持、客户服务、需求与供应计划。
- **做法**：用 AI 把分散的非结构化产品信息转换为结构化、统一、多维数据，放入 PIM；标准化产品应用、属性等字段。后续在 Salesforce 平台上小范围试点客户 Agent，为选定客户和供应合作伙伴提供 24/7 服务。
- **已公布效果**：官方未披露收入、毛利、匹配准确率或节省工时。这是已公布的架构和业务范围，不是 ROI 证明。
- **对本公司的启示**：建立化工品统一 `product_id`，将中英文名称、别名、CAS 号、牌号、规格、纯度、包装、应用、上下游、替代品、SDS/TDS/COA、法规标签和供应商物料号归一。新产品搜索 Agent 应先查这个产品图谱，再查外部信息。
- **不能直接类比**：Brenntag 有全球产品规模和专用 PIM 投入；中小贸易企业不必复制其系统复杂度，应先治理成交频率高、毛利贡献高的产品族。
- **证据等级**：B。
- **来源**：[Brenntag 与 Knowde 用 AI 改造化工产品数据管理（2024-04-07）](https://corporate.brenntag.com/en/media/news/brenntag-and-knowde-enter-into-a-strategic-partnership-to-master-product-data-with-ai.html)；[Brenntag 试点 Salesforce 自治 Agent（2024-11-05）](https://www.brenntag.com/en-cz/media/news/brenntag-implements-autonomous-ai-agents-on-its-salesforce-platform-as-first-customer-in-germany.html)

### 2. Synthomer：将邮件/PDF 客户订单转成可审批的 ERP 销售订单

- **企业/场景**：特种化学品供应商 Synthomer；客户通过邮件和多页 PDF 发送的非标订单录入。
- **做法**：文档 AI 抽取行级字段；Agent 联合物料目录、历史订单和客户资料，解析产品描述、处理计量单位差异，建议物料、客户及收货地址。员工可修改并批准，之后才触发 ERP 中的订单创建和后续流程。
- **已公布效果**：多产品线和多客户 Beta 测试的物料首次匹配率为 **98%**。这是测试结果，官方未披露投产后订单错误率、总工时或财务收益。
- **对本公司的启示**：可直接迁移到“客户询价/采购订单 -> 产品与客户匹配 -> 数量单位/交付条件校验 -> 人工确认 -> ERP 草稿”。需在界面显示原文证据、匹配信心度和字段级差异。
- **不能直接类比**：Synthomer 使用 SAP S/4HANA 及其生态；当前 ERP 不必照搬技术栈，但必须有稳定的物料、客户和订单 API 及审批状态机。
- **证据等级**：C（SAP 具名客户案例）。
- **来源**：[SAP 客户案例：Synthomer 销售订单 Agent（2026-06）](https://www.sap.com/italy/asset/dynamic/2026/06/26a59d25-567f-0010-bca6-c68f7e60039b.html)

### 3. Dow：运费发票核验 Agent，从小范围异常检测开始

- **企业/场景**：材料科学企业 Dow；将运费发票与合同费率、实际运输情况核对，识别重复计费、错用费率和异常附加费。
- **做法**：一个自治 Agent 监控带 PDF 附件的入站邮件并结构化数据，异常进入看板；员工再用问答 Agent 对预期费用、实际费用和差异进行追问。先选北美陆运这个相对简单的子集，而非一次覆盖全球所有运输方式。
- **已公布效果**：概念验证在不到 48 小时内导入 2024 年 8 个月、**4.3 万票运输**的费用数据，并在数秒内显示异常。Dow 称全面扩展后首年**预期**节约数百万美元；这是预测，不是已入账收益。
- **对本公司的启示**：可用相同模式核对“采购/销售合同-发票-收付款-物流单-杂费”。先选一种费用、一家承运商或一个产品线，建立“规则命中金额/实际追回金额/误报率”闭环。
- **不能直接类比**：Dow 每年运输支出达数十亿美元级别，1% 改善也可形成巨大金额；中小贸易企业应根据自身单据量和可追回金额测算经济性。
- **证据等级**：C（Microsoft 具名客户故事）。
- **来源**：[Microsoft Source：Dow 运费发票 Agent 案例](https://news.microsoft.com/source/latam/noticias-de-microsoft/impacto-de-la-ia-en-dow-copilot-identifica-millones-en-ahorros-de-costos/?ver=3.7.1)

### 4. Grupo Elfa：用生成式 AI 缩短 B2B 询价处理时间

- **企业/场景**：巴西医疗产品分销商 Grupo Elfa；每日大量客户询价的识别、定价与响应。
- **做法**：与技术伙伴建设 CotAI，将人工处理的报价流程结构化并用 AI 加速。案例公开页未披露完整的定价规则、人工审批节点和收入归因方法。
- **已公布效果**：询价处理时间从 **40 分钟降至 2-3 分钟**；上线 8 个月内公布新增收入超过 **1 亿巴西雷亚尔**。收入数据为厂商案例口径，未见独立审计和对照组说明。
- **对本公司的启示**：报价是贸易公司比通用办公助手更接近收入的高价值场景。可将客户询价与实时库存、最近采购成本、运费、账期、信用额度、目标毛利率和历史成交价相连，但只生成报价草稿和解释，价格越权需审批。
- **不能直接类比**：医疗分销的商品、监管和毛利结构与化工品不同；公布收入不能直接作为本公司 ROI 预测。
- **证据等级**：C（AWS 具名客户案例）。
- **来源**：[AWS 客户案例：Grupo Elfa 销售询价](https://aws.amazon.com/solutions/case-studies/grupo-elfa-a3data/)

### 5. Merck Life Science：产品相似度推荐与近实时供应链数据

- **企业/场景**：Merck KGaA 的生命科学业务；复杂产品目录搜索/比较、商品推荐和需求波动下的供应链分析。
- **做法**：将原本从 ERP 到分析系统约两天延迟的数据链路改为近实时数据整合，再构建预测、异常检测、推荐和相似产品模型。
- **已公布效果**：相似产品网格上线后，产品比较页流量增加 **400%**；两年内电商数据看板流量增加 **650%**。供应链库存或预测精度的量化结果未披露；页面流量也不等同于销售增长。
- **对本公司的启示**：新产品分析 Agent 不应只输出一篇报告，而应将外部市场信号与内部产品目录、历史询价、成交、毛利、库存和供应可得性关联，给出“相似/替代产品+匹配原因+业务证据”。
- **不能直接类比**：Merck 的电商流量与数据规模远大于传统贸易商；本公司更应用“高质量商机数、报价率、成交率、90/180 天毛利”衡量。
- **证据等级**：C（Google Cloud 具名客户案例）。
- **来源**：[Google Cloud 客户案例：Merck Life Science](https://cloud.google.com/customers/mercklifescience)

### 6. Covestro：用数据责任制、员工助手和 AI 学院把试点变成组织能力

- **企业/场景**：高分子材料企业 Covestro；采购、生产、销售、财务、研发和全员知识助手。
- **做法**：设立 Data Office，明确数据所有者，标准化数据结构并引入自动校验；以部门对数据产品负责的 data mesh 支撑 R&D 数据枢纽。CoVA 面向所有有公司终端的员工，并允许业务团队无代码创建和共享助手。AI Academy 用 12 个月课程和真实用例培养业务域 AI 专家。
- **已公布效果**：2025 财年 AI 优化流动性管理降低了**数百万欧元利息成本**；约 **100 名**员工参与 AI Academy。销售场景已开发客户交互准备/分析和新商机识别助手，但未披露销售量化效果。
- **对本公司的启示**：为每个核心数据域设置业务负责人（产品、客户、供应商、合同、发票、资金、招投标），对定义、完整率、更新时效和权限负责。设“业务场景 Owner + 数据 Owner + 工程师 + 风控/法务”小组，用真实 KPI 训练内部产品负责人。
- **不能直接类比**：Covestro 是全球生产企业，其自主生产线、研发模拟和数据网格规模不适合直接复制；本公司应借鉴运营模式，不是复制全套技术架构。
- **证据等级**：A（公司年报）。
- **来源**：[Covestro 2025 年报：Digital Innovation / Use of AI](https://annualreport.covestro.com/annual-financial-report-2025/en/report/management-report/fundamental-information-about-the-group/innovation/)

### 7. PTT Global Chemical：内部文档与会议助手，先从通用知识工作获取采用率

- **企业/场景**：泰国综合石化与炼化企业 PTT Global Chemical；文档分析、会议纪要、行动项和员工通用助手。
- **做法**：使用企业内部生成式 AI 分析文档，用办公 Copilot 生成会议纪要和行动项。公司强调化工企业在技术验证和谨慎投资后再扩大采用。
- **已公布效果**：文档分析速度可达每分钟 1 万词以上，个别文档分析任务节省一个工作日；会议纪要和行动项从数小时降至数分钟。未披露总用户量、采用率或财务收益。
- **对本公司的启示**：将群聊、合同、制度、产品资料和招标文件做成权限可控的知识助手，可较快建立全员使用习惯。但群聊中的承诺、报价、联系人信息和非正式结论必须区分，不得自动视为 ERP 事实。
- **不能直接类比**：阅读速度不代表业务准确率；合同、安全和产品法规问答必须另做引用完整性、版本时效性和拒答测试。
- **证据等级**：C（Microsoft 具名客户案例）。
- **来源**：[Microsoft 客户故事：PTT Global Chemical（2024-02-29）](https://www.microsoft.com/en/customers/story/1741358024158386060-pttgcgroup-azure-energy-en-thailand)

### 8. 中国中化：统一智能体底座，避免部门间重复建设

- **企业/场景**：中国中化；集团级知识、智能体与模型能力共享，覆盖农业、化工和经营管理。
- **做法**：建立“知识引擎-智能体引擎-AI 能力市集”三层解耦架构，统一管理 AI 资源、复用能力并打通系统；平台入选2025 年工信部人工智能应用典型案例。
- **已公布效果**：截至 2026-07，已支持**超百家单位**建设**超 4,000 个智能体**，模型访问量**超 3,000 万次**。这些是覆盖和使用量指标，未披露单个场景的准确率或 ROI。
- **对本公司的启示**：当前两个 Agent 就应共用统一的身份权限、模型网关、知识检索、工具注册、审计日志、评测数据集和成本计量。“能力市集”对中小企业可简化为一份受控的 Agent/工具清单。
- **不能直接类比**：中国中化是超大型集团；“4,000 个 Agent”不应成为本公司目标。小团队更应限制 Agent 数量，用用户采用、业务效果和维护成本淘汰低价值应用。
- **证据等级**：B（企业官网，同时引用工信部入选结果）。
- **来源**：[中国中化：智能体互联服务平台入选工信部典型案例（2026-07-22）](https://www.sinochem.com/sinochem/xwzx/zxdt/ywdt/2026/7/I1529521644316393472.html)

### 9. 深圳交易集团：标书客观项“AI 初审+专家复核”

- **企业/场景**：深圳交易集团/深圳公共资源交易中心；政府采购框架协议项目的资格和技术辅助评审。
- **做法**：AI 解析招标文件条款，抽取供应商投标文件的客观信息，将技术指标交叉验证，生成带风险预警和数据溯源的动态报告供专家参考。
- **已公布效果**：单个试点包含 13 个采购包、115 份标书；5 名专家用时 7 小时，AI 用时 **9 分 46 秒**。官方称该试点技术评审准确率 **100%**。这是规则清晰的液晶显示器框架采购单项试点，不代表复杂、主观型标书也能达到同样准确率。
- **对本公司的启示**：招投标 Agent 可优先做“商机去重与分类 -> 资质/时间/保证金/产品参数抽取 -> 内部能力匹配 -> 缺口清单 -> 原文定位”。评估结论必须展示条款原文、页码/段落、抽取值、判定规则和人工签字。
- **不能直接类比**：本案例是采购方的评审，本公司当前更接近投标方的商机筛选和响应编制；法律责任、数据可得性和成功标准都不同。AI 不应自动决定是否投标或代替法务/业务复核。
- **证据等级**：A（中国政府采购网）。
- **来源**：[中国政府采购网：深圳框采系统 AI 智能辅助评标试点（2025-04-09）](https://www.ccgp.gov.cn/zxdt/202504/t20250409_24415382.htm)

### 10. 中国华电：先统一模板、规则与权责，再把 AI 嵌入招采全链条

- **企业/场景**：中国华电；招标、投标、开标、评标、定标和监管全流程的智能采购。
- **做法**：智能采购系统与原采购计划、电子招投标系统集成；统一招标文件、评审要素、投标模块和数据归集标准；整合法规、行业规范、集团制度和历史案例，答案支持原文溯源；同时建立人机协同评审、数据安全等制度。
- **已公布效果**：官方称六大场景已于 2025-06-30 上线试运行并投入实战；未在该来源中披露节省工时、差错率、投诉率或财务收益。
- **对本公司的启示**：招投标文件的“可 AI 化”依赖于先将资格、商务、技术、价格、时间和风险要素模块化。对应到 ERP，应让招投标 Agent 将结果写入结构化“商机/项目”对象，而不只保存 PDF 摘要。
- **不能直接类比**：华电为大型央企，有全国产技术栈和集团制度统一能力；本公司应借鉴“标准+人机权责+系统集成”，不宜以全栈自研为目标。
- **证据等级**：A（国务院国资委网站，来源为中国华电）。
- **来源**：[国务院国资委：中国华电“AI+”智能招采实践（2026-05-12）](https://wap.sasac.gov.cn/n4470048/n22624391/n23826238/n23826274/n23859376/c35426557/content.html)

## 从案例抽象出的可迁移方法

### 方法 1：用业务闭环而非技术名词定义场景

每个场景用同一张用例卡立项：

| 字段 | 必填内容 |
| --- | --- |
| 业务事件 | 谁在什么时候，因何事触发流程 |
| 输入 | ERP 对象、文档、群聊、外部数据及版本 |
| 参照真值 | 人工已审批订单、已签合同、原始标书、已入账金额等 |
| AI 输出 | 提取、分类、匹配、预测、草稿或执行建议 |
| 人工关口 | 哪个角色对哪些字段/动作最终负责 |
| 写回 | 写回哪个 ERP 对象、草稿/已批准状态、幂等键 |
| 业务 KPI | 时长、正确率、误报率、人工复核率、金额、转化率 |
| 失败处理 | 低信心度、缺数据、冲突、越权或工具失败时如何中止与升级 |

### 方法 2：建立 AI 友好但仍以 ERP 为事实源的数据层

1. **主数据 ID 统一**：产品、客户、供应商、联系人、合同、订单、发票、收付款、物流单、招标项目都有不变的内部 ID，别名仅作映射。
2. **文档与业务对象关联**：PDF/图片/群聊切片不单独堆在知识库，必须关联 `entity_id`、文档类型、生效/失效时间、版本、来源和权限。
3. **事件和状态可追踪**：保存“已创建、已审批、已变更、已开票、已核销”等事件及时间，Agent 不从当前表格状态自行推断历史。
4. **数据契约与质量规则**：为每个数据产品定义字段含义、单位/币种/时区、空值含义、更新频率、负责人和校验规则。
5. **证据链单独存储**：保存模型版本、提示词/工作流版本、检索片段、工具调用、输出、人工修改和最终业务结果，支持回放与审计。
6. **最小权限读写**：默认只读；报价、合同、付款、客户承诺和对外发送均通过显式审批。

### 方法 3：用四级自动化边界管理 Agent

| 级别 | 能力 | 适合当前场景 |
| --- | --- | --- |
| L0 检索 | 只搜索、引用、定位原文 | 制度/SDS/历史合同问答 |
| L1 建议 | 生成摘要、匹配、风险和草稿，不写业务数据 | 新产品分析、招标商机评分 |
| L2 受控写入 | 人工确认后写入 ERP 草稿或执行低风险操作 | 询价、销售订单、客户跟进任务 |
| L3 有界自主 | 在预先批准的金额、对象、时间和操作范围内自动执行，异常即停 | 高成熟后的内部提醒、数据补全和低风险对账 |

在当前阶段，付款、开票、合同签署、对外报价/承诺和投标提交不应进入无人审批的 L3。

### 方法 4：用基线和对照组算价值

每个试点至少保留 2-4 周人工基线，上线后用相同产品线/类似人员作对照。建议指标：

- **效率**：端到端处理时间、等待时间、人工操作时间、每人每周处理量。
- **质量**：字段级准确率、首次通过率、误报/漏报率、人工修改率、回退/投诉率。
- **销售**：有效商机数、首次响应时间、报价率、中标/成交率、毛利率、新客户/180 天毛利。
- **采购/资金**：采购价差、缺货/积压、周转天数、逾期应收、异常费用追回金额。
- **风险**：越权调用拦截数、敏感信息泄露事件、不可追溯结论数、高风险建议的人工驳回率。
- **经济性**：`可确认年化收益 - 模型/算力 - 开发与维护 - 人工复核 - 风险预期损失`。

## 风险治理与中国合规边界

### 管理框架

- 可用 NIST AI RMF 的 `Govern - Map - Measure - Manage` 四个函数组织公司 AI 制度，并用其生成式 AI Profile 补充虚构、数据隐私、信息安全、知识产权和人机互动风险。来源：[NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework)；[NIST AI 600-1: Generative AI Profile](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)。
- 国内可将现行国家标准 **GB/T 46347-2025《人工智能 风险管理能力评估》**作为内部成熟度检查依据。来源：[全国标准信息公共服务平台](https://std.samr.gov.cn/gb/search/gbDetailed?id=40B74A27FD32BD79E06397BE0A0AB048)；[国家标准公开系统](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=120779016BBA61E4408DCECE3EAD92ED)。
- 若后续需要建立可审计的公司级 AI 管理体系，可参照 **ISO/IEC 42001:2023**，但当前不必以获证作为开发 Agent 的前置条件。来源：[ISO/IEC 42001:2023 官方页](https://www.iso.org/standard/81230.html)。

### 中国合规要点（不构成法律意见）

1. **内部使用与对外公众服务要分开判断。** 《生成式人工智能服务管理暂行办法》第二条明确，未向境内公众提供生成式 AI 服务的企业内部研发/应用不适用该办法。但若客服 Agent 向不特定境内公众开放，需重新评估适用范围、安全评估/算法备案等义务。来源：[国家网信办：生成式人工智能服务管理暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)。
2. **使用外部模型/SaaS 不等于数据责任转移。** 《网络数据安全管理条例》要求网络数据处理者建立制度并采取加密、备份、访问控制、安全认证等措施；涉及委托处理、重要数据和出境时另有要求。来源：[国家网信办：网络数据安全管理条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)。
3. **对外发布 AI 内容要评估标识义务。** 《人工智能生成合成内容标识办法》自 2025-09-01 施行，对符合其适用情形的服务提供者规定显式/隐式标识。本公司若让 Agent 生成并对外发布营销文案、图片或视频，应进入法务检查清单。来源：[国家网信办：人工智能生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)。
4. **群聊、客户联系人和合同数据应先分类分级。** 进入模型前至少区分公开、内部、机密/商业秘密、个人信息，按用途做最小必要字段、脱敏、保留期和权限继承。

## 对本公司场景的案例映射

| 建议场景 | 主要参考案例 | 建议自动化级别 | 首个验收指标 |
| --- | --- | --- | --- |
| 化工品主数据/文档归一 | Brenntag、Covestro | L1，人工合并确认 | CAS/牌号/规格匹配准确率，重复产品减少数 |
| 客户询价与报价草稿 | Grupo Elfa、Synthomer | L2，价格越权审批 | 首次响应时间、人工修改率、成交毛利 |
| 邮件/PDF 销售订单录入 | Synthomer | L2 | 字段准确率、首次匹配率、订单错误率 |
| 合同-发票-收付-物流异常核验 | Dow | L1 -> L2 | 误报率、处理时间、已确认/已追回金额 |
| 招投标采集与投标评估 | 深圳交易集团、中国华电 | L1 | 条款抽取召回率、原文引用正确率、有效商机数 |
| 新产品/新客户开发 | Merck Life Science、Covestro | L1 | 业务接受率、90/180 天报价、成交与毛利 |
| 群聊/制度/产品知识助手 | PTT GC、Covestro | L0 -> L1 | 引用正确率、版本命中率、无答案时拒答率 |
| 共用 Agent 平台与治理 | 中国中化 | 底座能力 | 复用率、单任务成本、审计完整率、上线周期 |

## 研究结论

这些案例共同指向一条路径：**先把 ERP 和文档变成有责任人、有版本、有权限、可追溯的数据产品；再将 AI 嵌入少数高频业务流程；先提建议和草稿，再在有证据的场景扩大自动化；最后用成交、毛利、现金和风险指标决定是否扩展。**

对当前公司而言，最有证据的优先级不是继续新建彼此独立的 Agent，而是：

1. 统一化工品/客户/供应商主数据与文档证据链；
2. 让招投标和新产品 Agent 共用权限、知识、工具、评测与审计底座；
3. 补上一个可直接连到收入/现金的流程型试点，优先考虑报价草稿、订单录入或合同-发票-收付异常核验；
4. 所有会影响价格、合同、资金、对外承诺和投标提交的动作，保留人工审批和可回放审计记录。
