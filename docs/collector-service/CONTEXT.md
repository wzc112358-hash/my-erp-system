# 招投标商机领域上下文

## 领域边界

本上下文覆盖公开招投标信息的采集、业务相关性判断、投标可行性初判和 ERP 展示。它不替代正式投标评审、法务审查、技术确认或最终报价决策。

## 统一语言

### 当前商机

仍在可参与时间内，且采购对象属于公司已经营或可能经营的化工产品。当前商机必须给出产品、截止时间、已知商务条件和投标资格初判。

### 可关注商机

产品具有业务或市场参考价值，但项目已经截止、结束，或当前有效性无法确认。可关注商机用于学习、储备、历史价格和市场情报，不表示当前仍可投标。

### 研判卡

Agent 基于公告正文和公开附件形成的结构化业务摘要。研判卡包含采购产品、数量、规格、交付条件、商务条件、历史参考、资格核对、结论和下一步动作。

### 投标可行性

公司参与当前项目的初步可行程度，分为：

- 初步可做：产品方向匹配，公开信息中未发现明确阻断条件，并且关键要求有可追溯的满足依据。
- 需要确认：产品可能可做，但技术、资格、供应、交付或商务条件至少有一项缺少公司侧证据。
- 初步不可做：公告存在明确阻断条件，例如仅限制造商，而公司没有公告认可的代理或授权路径；或项目已无参与机会。

投标可行性不是最终投标决定。没有公司侧证据时，Agent 不得把公告中的要求直接判定为已满足。

### 资格核对

把公告的硬性要求逐项与公司已知能力进行比对。常见核对项包括：

- 是否接受贸易商或代理商，是否要求制造商或原厂授权
- 技术指标、牌号、纯度、包装和使用装置是否能满足
- 同类供货业绩、合同或平台历史业绩
- 第三方检测、质检单、检验报告
- 中石油、中石化等平台准入或物料编码
- 危险化学品许可、危化运输和包装回收
- 交货周期、分批交付、付款、承兑、保证金和服务费

每个核对项只能是“有依据满足”“待确认”“有依据不满足”或“不适用”。

### 历史参考

公告、ERP 投标记录或已提供业务材料中的上次报价、上次中标价、中标单位、参与排名、品牌和过往供货记录。历史参考必须标明来源系统和匹配关系，只能作为经验依据，不能由模型推测，也不能单独证明当前资质满足。

### 历史投标参考

北京或兰州 ERP 中与当前公告存在相同产品、同类产品或相同采购方关系的既有投标记录。三种关系必须明确区分，避免把同一采购方的不同产品误当作同类供货业绩。

### 投标草稿

由当前商机预填、尚未成为正式业务事实的投标准备信息。投标草稿可以包含 Agent 建议值，但只有员工确认提交后才成为投标记录。

### 投标记录

公司已经决定参与或已经实际参与的项目记录，包含报价、费用、保证金、开标结果和复盘信息。投标记录不是采集公告的副本。

### 来源公告

触发投标准备的公开采购公告。来源公告通过稳定指纹与投标记录关联，用于追溯原文、避免重复建档和更新研判依据。

### 待确认项

决定是否参与前仍缺少的信息或公司侧证明。待确认项应写成可执行问题，例如“向厂家确认 350cst 指标和 25kg 桶包装是否满足”，不能只写“查看详情”。

## 业务判断顺序

1. 确认公告类型和截止时间，排除结果公告、处置公告和已无参与机会的项目。
2. 确认采购对象是否为公司已经营或可能经营的化工产品。
3. 提取产品、数量、规格、包装、用途、交付和商务条件。
4. 核对代理商、制造商、授权、业绩、检测、平台准入和危化要求。
5. 给出投标可行性、判断依据和具体下一步。

## 证据边界

- ERP 历史产品命中只能证明公司接触过该产品方向，不能单独证明当前技术指标或投标资质满足。
- 公告未写明接受代理商时，应标记待确认，不得默认接受。
- 公告要求制造商、业绩、检测、授权、平台准入或危化资质时，只有输入中存在公司侧证明才能标记满足。
- 数量、价格、日期、品牌、技术指标和历史中标信息必须能够回到公告正文、附件或已提供业务记录。
