# Product

## Register

product

## Users

恒化成员工、业务负责人和管理者在日常招投标巡检、商机判断、微信群汇报和 ERP 归档中使用本系统。用户的主要工作环境是登录多个招标/询价平台，处理验证码、账号态、附件和历史报价信息，并把可操作商机快速整理给王总或相关同事判断。

## Product Purpose

本产品把 ERP 业务系统和本地招投标采集助手连接起来，目标是从“手动逐站查看公告”升级为“本地 Agent 辅助采集、研判和汇报”。成功状态是：每天能明确哪些站点已巡检、是否有新公告、哪些公告命中公司产品、缺少哪些硬性判断信息、是否建议发群或继续深读附件，并能把员工反馈沉淀为后续规则。

## Brand Personality

务实、可信、克制。界面应服务高频业务操作，信息密度可以高，但重点必须清楚；任何 LLM 结论都要有证据和不确定性标记。

## Anti-references

不做营销页式界面，不用装饰性视觉压过业务内容，不把长过程日志和最终结论混在一起，不用无证据的“智能建议”替代员工判断，不把站点账号、模型密钥或敏感配置暴露在日志、安装包或页面输出中。

## Design Principles

- 结果先行：用户首先看到可行动商机、风险、截止时间和推荐动作，过程日志默认收起。
- 证据可追溯：每条候选和每个 LLM 判断都必须能回到页面文本、附件、截图或工具调用记录。
- 人工接管明确：遇到登录、验证码、短信、CA、安全验证或页面异常时，系统要明确暂停原因和下一步。
- 站点策略优先：不同招投标平台的栏目、登录方式、搜索习惯和失败模式不同，不能只靠通用脚本。
- 可降级运行：未配置 LLM 或外部工具失败时，仍能用入口 URL、浏览器采集、产品词库和人工反馈完成基础工作。

## Accessibility & Inclusion

默认按业务工具界面处理，文字对比度和控件可读性优先；关键按钮和状态不只依赖颜色；过程日志、长文本和附件摘要需要可折叠，避免用户为了看最终结果反复滚动。
