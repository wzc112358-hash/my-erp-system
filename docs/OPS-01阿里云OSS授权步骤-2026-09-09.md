# OPS-01 阿里云 OSS 授权步骤

日期：2026-09-09  
目标 Bucket：`erp-backup-henghuacheng`  
Endpoint：`oss-cn-hangzhou.aliyuncs.com`

服务器当前使用的 AccessKey ID（已遮盖）是 `LTAI********2pG1`。不要在聊天、截图或代码库中发送 AccessKey Secret。

## 一、找到对应 RAM 用户

1. 登录阿里云控制台，进入“访问控制 RAM”。
2. 打开“身份管理 > 用户”。
3. 逐个查看可能的备份用户，在“认证管理 > AccessKey”中找到 ID 首四位为 `LTAI`、末四位为 `2pG1` 的 AccessKey。
4. 不要新建或替换 AccessKey；当前问题是权限不足，不是服务器配置缺失。

## 二、创建最小权限策略

1. 在 RAM 控制台打开“权限管理 > 权限策略”。
2. 点击“创建权限策略”，选择“脚本编辑”。
3. 粘贴以下内容，策略名可填 `ERPBackupOSSWrite`：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:ListObjects",
        "oss:GetBucketInfo"
      ],
      "Resource": "acs:oss:*:*:erp-backup-henghuacheng"
    },
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject",
        "oss:GetObject",
        "oss:ListParts",
        "oss:AbortMultipartUpload"
      ],
      "Resource": [
        "acs:oss:*:*:erp-backup-henghuacheng/daily/*",
        "acs:oss:*:*:erp-backup-henghuacheng/weekly/*"
      ]
    }
  ]
}
```

4. 回到对应 RAM 用户，点击“新增授权”，选择 `ERPBackupOSSWrite`。
5. 不需要授予 `AliyunOSSFullAccess`，也不需要 `DeleteObject`；过期删除应由 Bucket 生命周期规则执行。

## 三、检查 Bucket 策略

1. 进入 OSS 控制台，打开 `erp-backup-henghuacheng`。
2. 在“权限控制 > Bucket 授权策略”检查是否有针对该 RAM 用户、ECS 公网 IP 或所有用户的显式“拒绝”。
3. 如果存在 Deny，不能仅靠 RAM Allow 覆盖；应修改 Deny 的对象范围，使 `daily/*`、`weekly/*` 可由该 RAM 用户写入和读取。
4. Bucket ACL 保持“私有”，不要改成公共读或公共读写。

## 四、配置生命周期

在“数据管理 > 生命周期”建立两条规则：

| 前缀 | 动作 | 建议保留期 |
| --- | --- | ---: |
| `daily/` | 删除当前版本 Object | 7 天 |
| `weekly/` | 删除当前版本 Object | 28 天 |

规则也会覆盖相邻的 `.sha256` 校验文件。若 Bucket 已开启版本控制，还要单独设置“历史版本删除”，否则旧版本仍会持续占空间。

## 五、授权完成后的验证

完成上述操作后通知维护人员执行：

```bash
/root/my-erp-system/scripts/erp-backup.sh
```

验证标准：

1. 命令退出码为 0。
2. `daily/当天日期/` 同时出现 `.tar.gz` 和 `.tar.gz.sha256`。
3. 脚本的远端 `stat` 校验成功。
4. 下载到独立临时目录后，SHA-256、`gzip -t`、四份 SQLite `PRAGMA quick_check` 均通过。

当前脚本在 OSS 失败时仍保留最近 7 份本地备份，但会返回非零退出码，避免再把云备份失败误报为成功。
