# ENG-01 自动发布配置步骤

日期：2026-09-09

## 已完成的工程改造

- GitHub Actions 在 `ubuntu-latest` 上运行前端、后端和本地助手测试。
- 编译与 Docker 镜像构建全部在 GitHub 托管机器完成，生产 ECS 不再执行源码编译。
- 发布包按 Git commit SHA 固定版本，上传前后均校验 SHA-256。
- 生产发布前自动生成四份 SQLite 数据库和附件的本地一致性备份。
- 新版本健康检查失败时自动恢复原配置和原镜像。
- 发布完成后删除上传的镜像压缩包，并清理无标签的旧镜像。

打开仓库 `wzc112358-hash/my-erp-system`，进入 `Settings > Secrets and variables > Actions`，点击 `New repository secret`，添加以下四项：

| Secret 名称 | 值 |
| --- | --- |
| `SERVER_HOST` | `182.92.78.227` |
| `SERVER_USER` | `root` |
| `SERVER_SSH_KEY` | 本项目 `.ssh/id_ed25519` 文件的完整内容，包括 BEGIN/END 两行 |
| `SSH_KNOWN_HOSTS` | 见下方固定主机公钥 |

`SSH_KNOWN_HOSTS` 的值为：


私钥只放入 GitHub Secret，不要粘贴到聊天、Issue、README 或普通变量中。

## 启用方式

当前工作区包含多批尚未提交的业务修改，因此本次没有代替你自动提交或推送。完成代码审查并提交后，推送到 `master` 会触发：

1. 自动测试；
2. 在 GitHub 构建不可变镜像；
3. 上传到服务器独立 release 目录；
4. 备份数据库；
5. 切换服务并执行健康检查；
6. 失败时自动回滚。

也可以在 `Actions > Verify and Deploy > Run workflow` 手动触发。Pull Request 只运行验证，不会部署生产。

## 首次验收

首次推送后在 Actions 页面确认全部步骤为绿色，并在服务器检查：

```bash
cat /root/my-erp-system/REVISION
docker compose -f /root/my-erp-system/docker-compose.yml ps
```

`REVISION` 应与 GitHub Actions 本次运行的 commit SHA 一致，所有容器应为运行或健康状态。
