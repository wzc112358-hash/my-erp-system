# OPS-01 阿里云 OSS 授权步骤

日期：2026-09-09  
目标 Bucket：`erp-backup-henghuacheng-1334472102397066`
Endpoint：`oss-cn-hangzhou.aliyuncs.com`
所属主账号 ID：`1334472102397066`

服务器当前使用的 AccessKey ID（已遮盖）是 `LTAI********2pG1`，属于 RAM 用户 `wzc112358`。该 RAM 用户未开启控制台登录。不要在聊天、截图或代码库中发送 AccessKey Secret。

## 一、确认专用 RAM 用户

1. 登录阿里云控制台，进入“访问控制 RAM”。
2. 打开“身份管理 > 用户”，找到 `wzc112358`。
3. 确认其 AccessKey ID 与服务器配置一致，并且未开启控制台登录。
4. 给该用户仅保留下文的自定义最小权限策略。

## 二、创建最小权限策略

1. 在 RAM 控制台打开“权限管理 > 权限策略”。
2. 点击“创建权限策略”，选择“脚本编辑”。
3. 粘贴以下内容，策略名可填 `ERPBackupOSSWrite`：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:GetObject",
        "oss:GetObjectAcl",
        "oss:PutObject"
      ],
      "Resource": "acs:oss:*:*:erp-backup-henghuacheng-1334472102397066/*"
    },
    {
      "Effect": "Allow",
      "Action": "oss:GetBucketInfo",
      "Resource": "acs:oss:oss-*:1334472102397066:erp-backup-henghuacheng-1334472102397066"
    }
  ]
}
```

4. 回到对应 RAM 用户，点击“新增授权”，选择 `ERPBackupOSSWrite`。
5. `oss:GetObjectAcl` 和 `oss:GetBucketInfo` 是旧版 `ossutil stat` 校验对象时需要的只读权限。
6. 不需要授予 `AliyunOSSFullAccess`，也不授予 `ListObjects` 或 `DeleteObject`；过期删除应由 Bucket 生命周期规则执行。

## 三、检查 Bucket 策略

1. 进入 OSS 控制台，打开 `erp-backup-henghuacheng-1334472102397066`。
2. 在“权限控制 > Bucket 授权策略”检查是否有针对该 RAM 用户、ECS 公网 IP 或所有用户的显式“拒绝”。
3. 如果存在 Deny，不能仅靠 RAM Allow 覆盖；应修改 Deny 的对象范围，使 `daily/*`、`weekly/*` 可由该 RAM 用户写入和读取。
4. Bucket ACL 保持“私有”，不要改成公共读或公共读写。

实际处理结果（2026-09-11）：原名 `erp-backup-henghuacheng` 不属于当前主账号，所以控制台不可见。已在当前主账号下创建带账号后缀的新 Bucket，并保持私有 ACL、阻止公共访问、同城冗余和 OSS 托管 AES-256 加密。服务器密钥本身已属于 RAM 用户，所以未更换密钥；已解除该用户的 `AliyunOSSFullAccess`，仅保留指向新 Bucket 的 `ERPBackupOSSWrite`。

## 四、配置生命周期

在“数据管理 > 生命周期”建立两条规则：

| 前缀 | 动作 | 建议保留期 |
| --- | --- | ---: |
| `daily/` | 删除当前版本 Object | 7 天 |
| `weekly/` | 删除当前版本 Object | 28 天 |

规则也会覆盖相邻的 `.sha256` 校验文件。若 Bucket 已开启版本控制，还要单独设置“历史版本删除”，否则旧版本仍会持续占空间。

## 五、授权完成后的验证

完成上述操作后通知维护人员执行：

```bash
/root/my-erp-system/scripts/erp-backup.sh
```

验证标准：

1. 命令退出码为 0。
2. `daily/当天日期/` 同时出现 `.tar.gz` 和 `.tar.gz.sha256`。
3. 脚本的远端 `stat` 校验成功。
4. 下载到独立临时目录后，SHA-256、`gzip -t`、四份 SQLite `PRAGMA quick_check` 均通过。

当前脚本在 OSS 失败时仍保留最近 7 份本地备份，但会返回非零退出码，避免再把云备份失败误报为成功。
